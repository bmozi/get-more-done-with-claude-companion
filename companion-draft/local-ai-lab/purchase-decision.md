Companion to Chapter56. This worksheet records a decision, not a hardware benchmark or a recommendation to buy John's configuration.

## Challenge the upgrade

1. Name one useful job the upgrade enables that the cheaper option cannot perform acceptably.
2. Identify whether the change buys memory capacity, storage capacity, speed, compatibility or convenience. State the evidence.
3. If the benefit is future exploration, write that explicitly. What would you be willing to spend even if it never saves money?
4. Could a smaller model, shorter context, sequential requests or external storage meet the need? Test quality again after changing the workflow.
5. What would persuade you to keep the current equipment instead?

Keep purchase status separate from test results. A machine that fits a model has passed a capacity condition; it has not yet proved useful answers, acceptable speed or a good buying decision.

## Before adding another model

Start with one primary language model. Record the unmet need before expanding the library.

- Current model and exact version:
- Observed failure or missing capability, with an example:
- Why another model might help:
- Same-input comparison and acceptance criteria:
- Added storage, loaded memory and maintenance requirements:
- Outcome: replace / retain for a distinct task / do not retain / unresolved:

Agent roles are not a model count. Distinguish stored models, loaded models and simultaneous requests. A research comparison does not establish that every reader needs the same library.
