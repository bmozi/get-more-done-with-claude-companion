# Chapter 33 practice guide

Build your first API application

## Objective

Run a local HTTP request and response, reject malformed draft records, and identify the additional work needed to connect the application to Claude.

## Inputs

- [README.md](../api-starter-lab/README.md)
- [fixtures.json](../api-starter-lab/fixtures.json)

## Practice and assessment

Run the complete, missing-year and extra-field commands. Before each run, write the expected state and explain why. Add a new authored fixture with two dates and establish the intended meaning before changing the validator. Keep the distinction between this local practice and an eventual authorized provider run.

**Change one condition:** The application may now save records automatically. Identify the new evidence and controls needed before that action. Valid JSON alone is not sufficient authorization or factual validation.

**Keep:** The contract, fixtures, actual run logs when available, and the distinction between local checks and a live API test.

## Record the attempt

Record date, product, interface, model shown, relevant settings, input version, actual output, checks, corrections, and unresolved questions. Do not put account identifiers or authentication material in the record.

Status: executed local HTTP fixture reference, not a Claude API call or human-learning trial.
