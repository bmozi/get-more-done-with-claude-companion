# Chapter 38 practice guide

Keep learning when Claude changes

## Objective

Update a workflow when Claude changes, preserve useful knowledge outside the interface, and decide what to relearn.

## Inputs

Use your own harmless notes or the self-contained fictional example in the chapter. Live product setup is not preconfigured by this guide.

## Practice and assessment

Create a maintenance note for one workflow: owner, current environment, source links, test cases, last verification date, and conditions that should trigger another review. Make the next review task concrete enough that someone else could perform it.

**Change one condition:** The preferred product is unavailable for a week. Use the saved sources and fallback to complete the essential task. Record what the tool had made easier and what knowledge still belongs to you.

**Keep:** A living method that can survive changes in the service. You began with one job you wanted to finish. You now have a way to choose a tool, give it useful work, inspect the result, and preserve what you learn for the next task.

## Record the attempt

Record date, product, interface, model shown, relevant settings, input version, actual output, checks, corrections, and unresolved questions. Do not put account identifiers or authentication material in the record.
