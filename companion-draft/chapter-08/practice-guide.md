# Chapter 8 practice guide

Show what good looks like

## Objective

Use examples and focused feedback to improve work while keeping preference, evidence, and authorship distinct.

## Inputs

- [Everyday collaboration and repair](../collaboration-lab/README.md)
Use your own harmless notes or the self-contained fictional example in the chapter. Live product setup is not preconfigured by this guide.

## Practice and assessment

Try the same principle on a structured task. The fictional note says, “We might meet Friday; Priya will check the room.” A useful extraction is “proposed meeting day: Friday; room-check owner: Priya; confirmed meeting day: unknown.” An unsuitable extraction is “Friday meeting confirmed; Priya booked the room.” Explain why the second version changes a proposal and an assigned check into completed decisions.

Ask Claude to apply that distinction to a new note: “We agreed to meet Monday. Nobody has accepted the room-check task.” The checked result should mark Monday confirmed and the owner unresolved. It should not copy Priya or Friday from the example. You are testing whether the rule transfers, rather than whether the wording resembles the sample.

**Change one condition:** The new note says only “Monday would be convenient.” The day returns to proposed. Explain which evidence changed. A confident writing style does not change the status of a decision.

**Keep:** A positive example, a counterexample with the error explained, and a new output checked against its source. Use the same habit when making a voice card; Chapter 12 develops the complete writing and revision exercise.
