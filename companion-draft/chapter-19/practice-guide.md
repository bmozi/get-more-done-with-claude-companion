# Chapter 19 practice guide

Turn a method into a skill

## Objective

Package a tested method as a skill, distinguish instructions from permissions, and keep the package small enough to inspect.

## Inputs

- [README.md](../skill-lab/README.md)
- [SKILL.md](../skill-lab/meeting-record/SKILL.md)

## Practice and assessment

Inspect the supplied skill folder, predict its worked example, and stage a practice copy. Test it in a practice project after checking the current installation mechanism for your chosen Claude environment.

Ask for a summary of notes containing one decision, one proposal, and one missing due date. Compare the result with the plain instructions from Chapter 18. The packaged version should earn its extra complexity through easier reuse or fewer omissions.

**Change one condition:** The user asks for a poem about a meeting. Should this summary skill apply? Explain the intended boundary and test it rather than assuming a description guarantees correct selection.

**Keep:** The package, its version, and a record of the actual environment used. The companion is a complete candidate package; runtime behavior and author acceptance remain separate checks.

## Record the attempt

Record date, product, interface, model shown, relevant settings, input version, actual output, checks, corrections, and unresolved questions. Do not put account identifiers or authentication material in the record.
