# Chapter 26 practice guide

Schedule work and find out what happened

## Objective

Specify a recurring task, detect missed or duplicate runs, and stop it cleanly.

## Inputs

- [packet.json](../evidence-check-lab/packet.json)
- Reviewer only: [answer-key.json](../evidence-check-lab/answer-key.json). Keep this out of the briefing input; consult it after recording your prediction and the result.
- [review-log-template.csv](../evidence-check-lab/review-log-template.csv)

## Practice and assessment

Write the run contract for a weekly fictional event briefing. Simulate three runs on paper: ordinary completion, unavailable source, and duplicate trigger. Define the output and notification for each.

**Change one condition:** The event is canceled. Identify how to disable the schedule and remove obsolete access. Then verify that the schedule is actually inactive in the product; a note saying “stop” is not sufficient evidence.

**Keep:** The schedule specification, run log, and stop procedure. Continuous work becomes useful when you can see its result and recover when it does not happen as intended.

## Record the attempt

Record date, product, interface, model shown, relevant settings, input version, actual output, checks, corrections, and unresolved questions. Do not put account identifiers or authentication material in the record.

Status: exercise design; live Claude execution and human learning trial not performed. The separate maintenance reference test log covers only that local program.
