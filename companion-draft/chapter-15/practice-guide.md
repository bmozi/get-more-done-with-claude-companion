# Chapter 15 practice guide

Make an artifact you can use

## Objective

Turn a conversation into an inspectable artifact and test behavior, accessibility, and persistence.

## Inputs

- [event-brief.txt](../shared/event-brief.txt)

## Practice and assessment

Use five input cases: zero, thirty, negative five, a decimal, and empty input. If you build the calculator, run them and record expected and actual results separately. If you sketch it, specify the expected response for each case and mark runtime results untested.

**Change one condition:** Supplies must be bought in packs serving ten people at $18 per pack, as in Chapter 13. Keep fixed costs at $150. With zero participants, buy zero packs and show $150. Thirty participants need three packs, so the total is $204. Thirty-one need four packs, so the total is $222. Always round the number of packs up to a whole pack; do not round the participant count. Test ten and eleven as well: $168 and $186. Preserve rejection of negative, decimal, and empty inputs. These are designed reference answers, not a report that an artifact has passed. A test only at an exact pack boundary would miss a broken rounding rule.

**Keep:** The brief, test cases, exported or saved artifact, and a note describing where it runs. Do not label it reliable merely because its first screenshot looks finished.

## Record the attempt

Record date, product, interface, model shown, relevant settings, input version, actual output, checks, corrections, and unresolved questions. Do not put account identifiers or authentication material in the record.
